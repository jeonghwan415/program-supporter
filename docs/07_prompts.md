## 1. 잘 통했던 요청 방식

| 방식 | 예 | 왜 좋았나 |
| :---- | :---- | :---- |
| 저장소 주소만 먼저 주기 | "https://github.com/jeonghwan415/program-supporter" | AI가 먼저 내려받아 구조를 읽고 무엇을 할지 물어봄 |
| 쓸 도구를 같이 말하기 | "mcp와 skill을 사용해서 … 워드클라우드 또는 썸트렌드, 또는 크롤링" | 크롤링(Firecrawl)·형태소 분석·워드클라우드를 실제로 씀 |
| 검토를 먼저 요구하기 | "변경된걸 내가 검토할 수 있게 해줘" | 바로 올리지 않고 보고서·패치·zip으로 받아 확인 |
| 잘 된 다른 저장소를 기준으로 주기 | "깃허브에 내가 만든 프로그램처럼 (safety helper)" | 폴더·문서 구조를 그대로 맞춰 줌 |
| 먼저 만들고 나중에 묻기 | "일단 만들어주고 다시 질문해줘" | 질문만 오가지 않고 결과물을 보며 결정 |

**아쉬웠던 점:** "제대로 안 된 것 같다"만 말하면 무엇이 문제인지 AI가 추측해야 해요 → **무엇이 기대와 달랐는지**(예: GitHub에 안 보임, 폴더가 정리 안 됨)를 한 줄 같이 쓰면 한 번에 고쳐요.

**③ 저장소 정리**
```
지금 제대로안된것같은데 지금 깃허브에 내가 만든 프로그램처럼 (예들을면 safety helper) 이것도 파일 폴더 다 해서 체계적으로 해주고 prd부터 벤치마킹, hand off, 와이드프레임등 해주면 좋을것같고

```
→ edu-safety-helper와 같은 구조로 정리: `index.html`, `PRD.md`, `CLAUDE.md`, `LICENSE.md`, `docs/02~08`, 와이어프레임 실제 캡처 16장, GitHub Pages 배포 설정

**② 프로그램 보완**
```
지금 이제부터 이 프로그램 서포터의 프로그램을 보완하는 작업을 할꺼야
일단 너가 가지고 있는 mcp와 skill을 사용해서 프로그램을 좀더 쉽고 체계적으로 만들어줬으면 좋겠고
워드클라우드 또는 썸트렌드, 또는 크롤링을 통해서 좀더 어휘 같은 것이 풍부하게 해줬으면 좋겠고
```

### 2026-11-03 (과제 문서에서 옮김, Claude Code · VS Code)

**프롬프트 ② 한 단락 PRD → Claude Code 첫 입력**

```
아래 한 단락 PRD대로 동작하는 프로토타입을 만든다.
[01 PRD의 한 단락 PRD 붙여넣기]
개발 조건
- 기능은 위에 적힌 3개만 구현한다. 그 외 기능은 추가하지 않는다
- 시작 전에 내가 결정해야 할 것이 있으면 3개 이내로 먼저 물어본다
- 그다음 파일 구조와 작업 순서를 보여주고, 내 확인을 받은 뒤 코드를 쓴다
- 화면 1개가 먼저 동작하게 만든다. 전체를 한 번에 만들지 않는다
- 설치·실행 명령을 README에 적는다
- 샘플 데이터가 필요하면 가짜 데이터 5건을 만들어 넣는다. 실제 기관 자료는 내가 따로 넣는다
```

Claude Code가 먼저 물어본 3가지와 고른 답:

| 질문 | 고른 답 |
| :---- | :---- |
| 계획서 문장을 어떻게 만들까? | 기본은 규칙(템플릿), API 키가 있으면 AI 다듬기 버튼 추가 |
| 어떤 형태로 만들까? | 더블클릭으로 여는 HTML 파일 1개 |
| 아동일지를 포함할까? | 처음엔 제외 → 센터 양식을 본 뒤 '프로그램 일지'로 포함 |

실제 개발 순서: ① 계획서 생성 3화면 + 별이 → ② 센터 양식(hwp) 반영 → ③ A4 인쇄 잘림 수정, README, 휴대폰 링크 → ④ 정보광장 벤치마킹 반영(형태 3종, 대·중분류, 키워드 18개, 캠프, 만족도, 워드, 결재란)

## 3. 과제용 공용 프롬프트

**프롬프트 ① 6질문 → 한 단락 PRD**

```
아래는 우리 팀 과제의 PRD 6질문 답변이다. 이것을 개발 착수용 「한 단락 PRD」로 정리해줘.
[Q1 누가 쓸까] 컴퓨터 조작이 서툰 40~50대 지역아동센터 생활복지사
[Q2 뭐가 답답한가] ① 작년 계획서를 복사해 날짜만 바꿔 씀 ② 목표를 숫자로 못 씀 ③ 계획서 내용을 일지·평가서에 다시 옮겨 씀
[Q3 어떻게 풀까] 버튼 몇 번으로 숫자 목표가 들어간 계획서를 만들고 일지·평가서까지 이어서 채워 주는 도구
[Q4 기능 3개] 계획서 자동 생성(근거 표시) / 일지·평가서 자동 연결(만족도 계산) / 센터 양식·결재란 그대로 인쇄·워드 저장
[Q5 어떻게 생겼나] 내용 고르기 → 계획서 확인 → 서류 만들기 3화면, 안내 캐릭터
[Q6 성공의 모습] 현장 선생님 3명이 서류 1세트를 기존보다 50% 이상 빠르게 완성
[＋ 데이터·제약] 무료, 설치 없음, 아동 개인정보는 받지 않음, 기존 작성 시간은 미확인
작성 규칙
- 한 단락, 5~8문장, 400자 내외
- "~하면 좋겠다"가 아니라 "~한다"로 단정해서 쓴다
- 기능은 3개만 쓰고, 나머지는 "이번 범위에서 제외한다"로 명시한다
- 내가 주지 않은 숫자·기능·데이터를 새로 만들지 않는다. 빈 내용은 "미확인"으로 남긴다
- 마지막 문장은 성공 판정 기준으로 끝낸다
- 출력은 한 단락 본문만
```

**프롬프트 ③ 인터뷰 내용 → PRD 수정안** (03 인터뷰 회차 2가 끝나면)

```
아래는 우리 팀의 현재 PRD와 기관 담당자 인터뷰 기록이다. 인터뷰에서 확인된 사실만으로 PRD를 고칠 부분을 찾아줘.
[PRD.md]
[03 인터뷰 회차 2 기록]
규칙
- 인터뷰에서 확인되지 않은 내용은 바꾸지 않는다
- 바꿔야 할 칸과 바꿀 내용을 표로 보여준다
- 인터뷰로 틀린 것이 드러난 가정은 "틀린 가정"으로 따로 표시한다
- 아직 확인되지 않은 것은 "다음 인터뷰 질문"으로 모아준다
```

## 4. 프로그램 안의 프롬프트

**프롬프트 ④ 'AI로 문장 다듬기'** (`index.html`의 `polishWithAI()`)

```
너는 지역아동센터 프로그램 계획서 문장을 다듬는 도우미다. 사회복지 현장 계획서 문체(~한다)로 짧고 쉽고 구체적으로 고친다.
규칙: 목표에 들어 있는 숫자(인원, 비율, 회기, 권수, 횟수)는 절대 바꾸지 않는다. 목표 개수와 순서를 유지한다.
입력에 없는 사실(예산, 기관명, 통계, 외부 기관)을 만들지 않는다. requests에 적힌 요청은 methods에 반드시 남긴다.
methods는 줄마다 '• '로 시작하는 목록 문자열로 쓴다. effects는 3~4개 문장 배열로 쓴다.
```

| 안전장치 | 내용 |
| :---- | :---- |
| 답 형식 고정 | 필요성·목적·목표·운영 방법·기대효과만 JSON 형식으로 받음 |
| 숫자 보호 | 목표 개수가 바뀌면 적용하지 않음. 숫자는 지시문으로 바꾸지 못하게 함 |
| 사용자 확인 | 바뀐 칸은 노란색, [되돌리기]로 원래 문장 |
| 실패 처리 | 키 오류·요청 초과·네트워크 오류는 쉬운 말로 알리고 원래 계획서 그대로 |

## 5. 담당자용 프롬프트

**프롬프트 ⑤ 새 키워드 문장 만들기** → 결과를 `index.html`의 `KEYWORDS`에 붙여 넣음

```
지역아동센터 프로그램 키워드 '[키워드]'의 계획서 문장 묶음을 아래 형식으로 만들어줘.
- cat: 보호/교육/문화/정서지원/지역사회연계 중 하나, sub: 중분류
- titles: 프로그램 제목 2개
- need: 필요성 1문장, purpose: 목적 1문장 (~한다 문체)
- goals: 숫자로 확인할 수 있는 목표 2개. '참여 아동 {k}명({p}%) 이상이 ~한다.' 형식, 평가 방법(m), 비율(p)
- sessions: 8회기 [주제, 활동 내용]. 첫 회기는 오리엔테이션, 마지막은 마무리
- materials, effects 3개, survey 아동용 질문 2개
- 초등학생 수준, 비용이 적게 드는 활동, 안전 수칙이 필요하면 extraMethod에 1문장
```

**프롬프트 ⑥ 어휘 분석 결과 → 문장 도우미 초안** (v2.1에서 씀)

```
아래는 지역아동센터 공개 자료(사업계획서·관찰일지 예시·작성 가이드)에서 자주 나온 낱말과 빈도다.
[data/vocabulary/빈도분석.json의 top_nouns, new_nouns]
이 낱말을 참고해 [필요성 / 일지 관찰 의견 / 평가 의견] 문장을 [영역 / 묶음]별로 4개씩 새로 써 줘.
규칙
- 원문 문장을 옮기지 않고 새로 쓴다
- 40~50대 선생님이 바로 쓰게 쉬운 말로. '도모·함양·고취' 같은 한자어는 풀어 쓴다
- 일지 문장은 느낌이 아니라 보인 행동으로, 아동 이름 대신 '○○ 아동'
- 문체는 계획서 '~한다', 일지·평가서 '~하였다'
- 숫자나 사실을 지어내지 않는다
```
